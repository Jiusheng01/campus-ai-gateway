# Campus AI Gateway 控制台设计约定

本轮基于 main `9d44669`，服务校园信息化管理员与使用模型的 Account。管理员的主要任务是发布 Virtual Model、维护 Provider 和 Route、管理 Tenant 资源；Personal Console 帮助 Member 完成模型接入与个人记录查询。两个工作区共享组件，导航和授权范围分别保留。

## 视觉方向

把模型服务关系与可执行操作放在首位。采用清晰的蓝色操作、稳定的中文排版和紧凑的数据区域；校园插画只用于登录和少量欢迎位置。常规列表页使用简洁标题与工具栏。视觉重点留给真实指标和当前任务，不为每块信息添加相同的装饰。

| 角色 | 浅色基准 | 使用约定 |
| --- | --- | --- |
| 页面背景 | `#F5F7FB` | 工作区底色 |
| 内容表面 | `#FFFFFF` | 表格、表单和详情 |
| 主文字 | `#121C32` | 标题、正文、关键数字 |
| 主要操作 | `#315FEA` | 当前导航、提交、可交互焦点 |
| 成功文字 | `#087F6D` | 成功标签；`#16A085` 可用于非文字强调 |
| 分隔线 | `#DCE3EE` | 内容边界；不单独承担状态含义 |

警告与错误沿用现有语义 Token；背景、文字、描边与图表颜色一起适配深色主题。使用已有 `data-theme`，避免增加页面私有近似色。颜色基准是设计方向，实际组合必须验证普通文本 4.5:1、大字及必要非文本状态 3:1；未知、失败和零分别呈现。

字体使用现有中文系统字体栈，补充 `Noto Sans SC` 回退，不依赖外部字体加载。页面标题 26px，区块标题 17px，正文 14px，表格 13–14px，辅助信息 12–13px，指标 32px；长 Alias、Request ID 等使用等宽字体并保留完整阅读和复制方式，普通标签不使用等宽字体。数字使用等宽数字特性。

桌面侧栏 240px，可折叠；顶部高度统一为 64px。内容左对齐，宽度随视口调整并设合理上限。8px 为间距基准，主要内容区域间隔 16–24px；容器内间距 16–24px。容器圆角 12–16px，控件使用较小圆角。文字保持可读，通过减少重复标题、插画和多余间隔提高密度。

```text
管理员桌面
┌────────────┬───────────────────────────────────────────┐
│ 工作区导航 │ 当前工作区 / 页面       搜索 主题 账号    │
│            ├───────────────────────────────────────────┤
│ 模型服务   │ 页面标题 + 简短上下文            主操作  │
│ 治理审计   │ 搜索与筛选                               │
│ 账号系统   │ 表格 / 模型关系 / 当前任务                │
│            │ 数量、分页与操作结果                     │
└────────────┴───────────────────────────────────────────┘
```

个人工作区沿用这个结构，用模型接入步骤与个人数据替代管理导航。小屏导航为可关闭的覆盖面板；工具栏换行、表格在容器内横向滚动、抽屉宽度不超出屏幕。动效 120–200ms，遵循减少动态效果偏好。按钮与模态交互必须支持键盘、焦点限制、关闭后恢复焦点及清楚的禁用原因。

## 对照需求后的取舍

- 保留需求指定的蓝白 SaaS 方向和现有组件，不为追求新风格引入衬线标题、复杂渐变或新 UI 框架。
- 初始代码在常规页面默认展示校园插画；改为仅在合适的欢迎位置使用，让模型发布与检索在首屏更明显。
- 保留运营概览的四个真实指标，常规管理页减少占据首屏的大型统计卡，优先显示操作和列表。
- 用 Alias、渠道、Upstream Model 和线路层级表达本产品的服务关系；不根据模型名称猜测能力，不将静态可路由或最近测试结果写成实时健康。
- 不整体替换样式系统。先在公共 Token、Shell 与模态基础完成兼容整理，再按任务迁移页面；每批保持样式契约与页面测试通过。

## 审计与复用边界

以下来自静态代码审阅，不能替代浏览器布局检查。浏览器证据记录在本轮本地任务的 research 目录。

| 已有能力 | 本轮处理 |
| --- | --- |
| Shell、独立导航、角色过滤、主题与侧栏偏好 | 复用，整理标题层级、移动焦点与重复品牌内容 |
| PageBanner、Panel、StatCard、Table、Field | 复用组件接口，统一字号、间距与语义颜色 |
| Modal、Drawer、ConfirmDialog、Toast | 复用，补齐 Drawer 的 Tab 焦点限制及异步反馈 |
| EmptyState、ErrorState、SkeletonRows | 复用，区分首次空状态、筛选无结果和请求失败 |
| PublishModelWizard、ProviderForm、ProviderModelsPanel | 复用业务流程，改善分组、选择、失败重试与发布后反馈 |
| RouteEditor、模式切换差异、409 草稿保留 | 保留；后续补任意编辑的最终保存差异确认 |
| Console 模型示例、一次性 API Key 展示 | 保留；补完整模型 ID 复制与连续接入导航 |
| 页面交互测试、样式契约 | 保留，不新增缺失样式白名单 |

当前样式包含早期基础规则和后续重设计规则。`PageBanner`、`StatGrid` 的下边距与外层 `.stack` 间距叠加；辅助标签有 10–11.5px 的字号；多个状态图标和 Banner 使用固定浅色；`--border-subtle` 被引用但没有定义。按所属组件就地整理，避免在文件末尾不断覆盖。

## 数据与能力边界

- 概览使用 `/admin/status` 的依赖探测、统计和配置计数；Route 总数可按完整 Virtual Model 的 `route_count` 汇总。趋势使用已有趋势接口；整体 P95 不从分桶 P95 平均计算。
- `/admin/status` 的日统计按数据库会话日界计算，趋势按浏览器时区。前端说明统计窗口，不把它们称为同一窗口。状态接口没有依赖响应延迟、历史健康或整体健康保证。
- Provider 已有分页总量、候选模型数量、Credential 摘要、最近测试和删除影响接口。Provider Circuit 只是本实例内存状态；无观测不表示健康或异常。
- Virtual Model 列表已有路由计数、静态可路由和配置版本。当前部分 Provider 选择器只取前 100 或 200 条；使用既有完整读取或分页读取解决。模型列表仍需分页、完整 Alias 复制和直接测试入口。
- 管理 Request Record 已有过滤聚合与导出；Personal Console 的记录接口没有总量字段，只能据返回页判断下一页，不能虚构总页数。
- 个人模型接口只公开允许展示的模型字段。个人页面不得通过管理接口补 Provider、Route 或其他 Account 的数据。
- 个人资料现有身份接口与系统设置现有认证配置均为只读；本轮整理展示和安全设置，不虚构资料保存或系统配置保存能力。
- API Key 原文只在创建响应临时展示，Credential 只写。Tenant 承担 Quota 和 Rate Limit；个人 Usage 与 Tenant 共享 Quota 分开。

## 首批实施与验收

先统一公共样式和双工作区 Shell，再优先完成 Virtual Model 发布与管理，同时改善 Provider 工作流及服务概览。首批通过真实浏览器及检查后直接继续，用户已取消任务 08 的人工确认暂停。

测试使用已确认的页面交互、样式契约和真实浏览器边界。先写行为失败用例再做对应改动，不为文档或纯视觉常量编写镜像测试。重点检查发布、筛选、复制、失败重试、版本冲突、只读角色和焦点行为。浏览器覆盖 1366×768、1440×900、1920×1080、768px 与 390px，以及浅深色、空数据、加载和错误；首批比较相同角色、数据和主题的前后截图。

开发代理必须保持 `changeOrigin: false`，严格区分 `/admin` API 与 `/admin-ui/` 资源，并代理个人接口；构建只在独立工作区执行，不提交嵌入构建产物。现有 18088 环境、后端接口与安全边界不在本轮修改范围。
